# 7. Legacy KLMC3

The `Legacy KLMC3` section is not a nostalgia archive. It exists to document the scientific and
operational ancestry of `patina`.

This section should answer three questions:

1. What legacy workflows or assumptions are still scientifically relevant?
2. Which runtime contracts came from the older codebase and still shape current data?
3. Which behaviors are intentionally being retired rather than preserved?

Current policy:

- preserve provenance and migration context
- avoid preserving private path assumptions
- rewrite operational instructions into generic language before they become public guidance
